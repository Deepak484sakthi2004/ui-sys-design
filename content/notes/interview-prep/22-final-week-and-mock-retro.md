# Chapter 22: Final Week & Mock Retro

> **Relearning log.** My instinct in the last week is to cram new material. That's the wrong move —
> the final week is about **staying warm, consolidating, and managing energy/logistics**, not
> learning. Cramming a new DP variant the night before just adds anxiety and displaces sleep, which
> hurts every round. The recovery: a deliberate taper — light reps to keep the edge, re-read my own
> [cheatsheets (App A)](A-cheatsheets.md) and mistakes log, rehearse my top stories aloud, and treat
> sleep and logistics as part of the prep. This chapter is my final-week protocol plus the mock-retro
> method I run after every practice round.

---

## 22.1 The final-week taper

| Days out | Focus | Avoid |
|----------|-------|-------|
| **7–4** | One mock per day (mixed); re-attempt flubbed problems from the [drill log (Ch 13)](13-coding-drills-and-mock-log.md); rehearse top 8 stories aloud | New hard topics |
| **3–2** | Re-read [cheatsheets (App A)](A-cheatsheets.md) + [mistakes log (Ch 2)](02-study-plan-and-tracker.md); 1–2 easy/medium problems to stay warm; one design out loud | Marathon sessions; new patterns |
| **1 (day before)** | Light: skim cheatsheets, re-read story headlines, prep logistics, **stop early**, sleep | Anything hard, late nights, caffeine late |
| **Interview day** | Warm up with ONE easy problem you know cold; eat; arrive/login early | Last-minute cramming |

> The night-before rule I enforce: **no new material, and stop studying by early evening.** Sleep is
> a performance multiplier across every round. A rested B+ beats an exhausted A.

---

## 22.2 Day-before checklist

```
Logistics
[ ] Confirm time zone, format (virtual/onsite), and the schedule of rounds
[ ] Test the video/coding tool (CoderPad/HackerRank/Meta's tool) — audio, screen share, editor
[ ] Backup: phone hotspot, charged laptop, charger, water
[ ] Quiet room, good lighting, door closed; tell housemates/family the schedule
[ ] Recruiter's number handy in case of tech issues
Materials (for behavioral recall, not cheating)
[ ] Story bank headlines visible (titles only — to jog memory, not to read from)
[ ] Cheatsheet skimmed: complexity table, latency numbers, design 7-step, STAR
Body
[ ] Sleep 7–8 hrs; light breakfast; hydrate; bathroom before each round
```

## 22.3 Interview-day round-by-round mental checklist

- **Coding:** run the [C-C-C-C-C script (Ch 3)](03-problem-solving-framework.md) — clarify, derive
  target complexity from n, brute force out loud, get buy-in, code clean, **trace an example**,
  state complexity. Narrate continuously.
- **Design:** run the [7-step script (Ch 14)](14-system-design-framework.md) — scope, estimate,
  API, data model, HLD, **pick the bottleneck and deep-dive**, wrap with failure/10×. Narrate the
  step you're in; frame every choice as a tradeoff.
- **LLD:** [clarify → entities → relationships → the one pattern → concurrency (Ch 17)](17-ood-solid-and-patterns.md).
  Restraint.
- **Behavioral:** headline first, then STAR, Action-heavy, quantified Result, "I" not "we"; use the
  [company's value words (Ch 20)](20-company-signals-and-leadership-principles.md).
- **Between rounds:** reset. A bad round is one signal of four/five — don't let it bleed into the
  next. Breathe, water, move on.

> The "don't let one round bleed into the next" rule is real and hard. Each round is scored
> independently by a different person; a rough coding round does **not** doom the loop. Treat every
> round as a fresh start. Carrying the last round's failure into the next is how one bad round
> becomes three.

## 22.4 The mock retro method (run after every practice round)

After each mock, before I forget, I run a 5-minute retro and feed it into the
[mistakes log (Ch 2)](02-study-plan-and-tracker.md):

```
1. OUTCOME      Did I solve it / drive it? In time?
2. BEHAVIOR     Where did I go silent? Did I narrate? Did I ask for buy-in / state complexity?
3. ROOT CAUSE   Tag each flub: communication / recognition / careless / algorithm / time
4. THE ONE FIX  The single most impactful change for next time (pick ONE, not ten)
5. RE-ATTEMPT   Schedule the problem per the spaced-repetition rules if I failed/hinted
```

> The discipline is **picking ONE fix per retro.** "Improve everything" changes nothing; "always
> state complexity as my last sentence" is a concrete habit I can actually install. Habits stack one
> at a time.

## 22.5 Managing nerves & mindset

- **Reframe:** the interviewer is a future colleague who *wants* me to succeed, not an adversary.
  Most are rooting for a hire (it's work off their plate).
- **Think out loud as anxiety control:** narration both scores points and keeps my mind from
  spiraling in silence.
- **It's a sample, not a verdict:** a single loop is a noisy measurement of a real engineer. Reapply
  after the cooldown if it doesn't land — many strong engineers pass on a second attempt.
- **Confidence from preparation, not bravado:** the cheatsheets and the rehearsed scripts *are* the
  confidence. I've done the reps.

---

## 22.6 After the loop

- **Write a self-retro** within an hour: each round, what went well, what I'd change, which questions
  I got (for next time / next company).
- **Send a brief thank-you** to the recruiter; reiterate interest and fit.
- **If it doesn't land:** ask for feedback, note the cooldown period (typically 6–12 months), and
  feed the gaps back into the [study plan (Ch 2)](02-study-plan-and-tracker.md). A "no" is data, not
  a verdict on my career.
- **If it does:** [negotiation (Ch 21)](21-negotiation-and-offer.md) — don't accept on the call.

## Interview Drills

- **D22.1 [E]** Write your day-before checklist and verify your coding-tool setup *now*, not the
  night before.
- **D22.2 [M]** Run a full mock loop simulation (1 coding + 1 design + 1 behavioral, timed) and do
  the 5-step retro on each.
- **D22.3 [M]** After your next mock, name the ONE fix and turn it into a one-sentence habit.

## Key Takeaways

1. **The final week is taper, not cram** — stay warm, consolidate, rehearse stories, protect sleep.
   No new hard material.
2. **Sleep and logistics are part of the prep;** test the tooling, stop studying early the night
   before.
3. **Each round is scored independently** — don't let one bad round bleed into the next; reset
   between rounds.
4. **Run a 5-step retro after every mock and pick exactly ONE fix** — habits install one at a time.
5. **A loop is a noisy sample, not a verdict.** Prepare, perform, retro, and reapply if needed.
